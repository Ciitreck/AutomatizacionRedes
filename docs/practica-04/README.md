# Practica 4: Exploracion de comunidades, documentacion y recursos de colaboracion

## 1. Proposito de la practica
El objetivo de esta practica es aprender a buscar informacion segura en internet, saber que paginas de programacion y redes son confiables, y armar una base de conocimientos en equipo para resolver los errores de codigo que salgan mas adelante en las siguientes practicas.

## 2. Relacion con el proyecto integrador
Esta practica nos ayuda a saber donde buscar ayuda cuando Python no quiera conectar con los routers de GNS3 o cuando los scripts nos den errores, asi no nos quedamos trabados en el desarrollo del proyecto.

### Analisis de la tabla
* **Cual consideras mas util para dudas de Python y por que:** La documentacion oficial de Python, porque la escribieron los mismos creadores del lenguaje y estas seguro de que no tiene fallas.
* **Cual consultarias para resolver un problema de GNS3 y por que:** El foro de GNS3 o Stack Overflow, porque ahi entran ingenieros de redes que ya arreglaron los mismos errores de conexion que nos salen a nosotros.
* **Por que no conviene copiar directamente una solucion sin comprobarla:** Porque puede estar hecha para otra version de Python, puede usar variables que no tenemos o puede descomponer la configuracion que ya funciona en nuestra computadora.

## 4. Estrategia de solucion del problema hipotetico (Parte 6)

| Elemento | Respuesta del equipo |
| :--- | :--- |
| **Problema identificado** | El programa de la practica 3 encuentra R1 y R2 pero falla al buscar un equipo por su nombre. |
| **Palabras clave para realizar la búsqueda** | python buscar valor en diccionario, python encontrar elemento por nombre en lista diccionarios. |
| **Documentación o comunidad que consultarían** | La documentacion oficial de Python en la parte de diccionarios y despues Stack Overflow. |
| **Información que revisarían en el código** | Revisariamos si escribimos bien las mayusculas, si hay espacios extra en el nombre o si falto un ciclo. |
| **Tipo de ejemplo o solución que buscarían** | Un codigo simple que enseñe como usar un ciclo for y un if para comparar el nombre que pide el usuario. |
| **Cómo comprobarían que la solución funciona** | Corriendo el programa en la web o consola poniendo nombres en minusculas, mayusculas y nombres que no existan. |
| **Cómo documentarían la solución encontrada** | Subiendo el codigo arreglado a GitHub y poniendo una nota en el mensaje que diga que ya busca por nombre. |

## 5. Aprendizajes obtenidos (Parte 7)
Aprendimos que no debemos buscar ayuda en cualquier pagina de internet porque hay mucha informacion vieja o equivocada, ahora ya sabemos usar las tablas para ver si una fuente es de confiar y tenemos un plan ordenado para buscar errores cuando Python no encuentre los dispositivos de red.

## 6. Conclusiones individuales

### Carlos Cobos
La diferencia mas grande entre la documentacion de fabrica y un foro de internet es que el manual oficial nunca se equivoca porque lo cuidan los creadores de Python. Para saber si una pagina de programacion es buena yo me fijaria en quien la escribio, si trae ejemplos claros que funcionen y si no es un blog viejo de hace muchos años. Cuando me trabe programando en Python voy a entrar a los foros para buscar los codigos de otras personas y ver como solucionaron sus problemas de forma facil. Guardar todas estas soluciones en nuestra cuenta de GitHub es muy util porque asi no se nos pierden las cosas y todo el equipo puede entrar a revisar los apuntes cuando algo falle. En las siguientes clases usaremos mucho estas paginas para saber como poner los comandos de automatizacion de redes sin equivocarnos en el codigo.
